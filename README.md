# order-check-vba

**Automated cross-checking of manufacturing-request sheets in Excel VBA.**

Every week, a hand-built manufacturing request (`.xlsx`) has to match a reference workbook generated by macros (`.xlsm`). Comparing hundreds of rows by eye is slow and error-prone, so this project turns the review into two one-click macros that flag every mismatch, highlight it on a copy of the file, and write a filterable report.

> The macros read two workbooks, apply a fixed set of business rules, and report what breaks them. **The reference file is treated as ground truth, and neither input file is ever modified.**

## What's inside

| File | Macro | Scope |
|---|---|---|
| `src/HospitalCheck.bas` | `CheckHospital` | **Overseas section** - vial and package structure, labels, numbering, and a file-to-file comparison |
| `src/DomesticCheck.bas` | `CheckDomestic` | **Domestic section** - numbering continuity and row-by-row comparison against the reference |

## How it works

1. Run the macro (`Alt+F8`).
2. Pick the **reference workbook** (`.xlsm`), then the **workbook to review** (`.xlsx`).
3. The macro opens both files read-only with macros disabled, parses the sheet, and runs the checks.
4. Results land in a new sheet in your checker workbook, and a **color-marked copy** of the reviewed file is saved next to the original.

| Output | Details |
|---|---|
| Report sheet | `검증결과` (overseas) / `국내검증결과` (domestic): one row per finding with severity, location, and an explanation; auto-filter enabled |
| Marked copy | Saved next to the original as `<name>_검증표시` (overseas) or `<name>_국내검증표시` (domestic), same file extension. If that folder is not writable, it falls back to the checker workbook's folder. Cells are color-coded and each flagged block carries a cell comment with the reason |

Color legend: light red = rule violation, dark red = emphasized error cell (for example a wrong mCi label), yellow = differs from the reference.

## Checks

### `CheckHospital` - overseas section

**Structure rules (applied to both files)**
- **Vial grouping** - every vial (up to 4 rows) must contain a single hospital, date, weekday, and strength.
- **Label arithmetic** - the printed mCi on a vial must equal `rows x strength`.
- **Package integrity** - a package holds at most 2 vials, and vials in one package must not mix hospital, date, weekday, or strength.
- **Merged-cell consistency** - a package's merged range must cover exactly the rows it groups.
- **Orphan rows** - rows with data that belong to no vial are reported.
- **Note numbering** - the numbers in the remark cells must match the row numbers in column A.
- **Leftover vials** - several partial vials (under 4 rows) for the same hospital, weekday, and strength are reported as an advisory.

**File comparison**
- Rows per hospital / weekday / strength, and the **grouping pattern** (for example `4+4` vs `4+1`), compared between the two files.
- Dates compared directly when both files are for the same order date. When the order dates differ, the macro checks that dates shifted by the **same number of days** instead.
- Rows with no hospital name are intentional placeholders, so they are excluded from comparison.

### `CheckDomestic` - domestic section

- Locates the domestic block automatically: it starts after the last row of the overseas distributor and ends before the summary table.
- **Numbering** - sequence numbers must continue from the overseas section in steps of 1, with no gaps, blanks, or non-numeric values.
- **Row comparison** - rows are paired by **hospital, weekday, strength, and distributor**, and the row order is ignored.
- Rows that don't match perfectly are paired with the closest candidate and labeled with *what* differs, in this order: **strength -> weekday -> distributor -> hospital name**.
- Rows present in only one file are reported separately.
- When a hospital name differs, the report also states whether each spelling exists in the workbook's hospital-name list, to tell a real error from a spelling variant.

## Design notes

- **Non-destructive by design.** Inputs are opened read-only with `AutomationSecurity` set to disable macros, and all highlighting goes onto a saved copy.
- **Tiered matching instead of a flat diff.** Pairing rows from strictest to loosest key turns "row 41 differs" into "row 41 has the wrong weekday", which is what a reviewer actually needs.
- **Order-independent comparison.** Rows are compared as multisets of keys, so a reordered sheet does not create noise.
- **Explainable output.** Each finding carries severity (error, difference, advisory), location, and a plain-language reason, both in the report and as a comment on the marked cell.
- **Self-contained.** Pure VBA with no external dependencies, suitable for a locked-down corporate environment.

## Usage

1. Create (or open) a checker workbook and import the modules: `Alt+F11` -> File -> Import File -> `src/*.bas`.
2. Run `CheckHospital` or `CheckDomestic` with `Alt+F8`.
3. Select the reference `.xlsm`, then the `.xlsx` to review.
4. Read the report sheet and open the marked copy to see each flag in context.

If Korean text is garbled after importing, save the `.bas` files as ANSI (CP949) and import again.

## Notes and limitations

- Built for one specific workbook layout. Column letters (A, C, E, H, J, K, L-Q), the starting row, and the sheet names are fixed in the code and need adjusting for other files.
- The macro UI, report text, and code comments are in Korean, the original working language.
- Client and distributor names in this repository are anonymized placeholders. No real data is included, and Excel files are excluded through `.gitignore`.
